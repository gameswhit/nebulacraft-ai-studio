Workflow

How a NebulaCraft session flows

The agent operates as a real teammate: plans, executes, verifies, then ships. You stay in control at each gate.

1

Describe

Tell the studio what you want — feature, bug, migration. Drop in repo URL or upload a folder.

2

Plan

The MiMo planner decomposes the goal into ordered diffs and acceptance criteria you approve.

3

Build

Each diff runs in a sandbox with build + test. Failures self-correct via tool-use loops.

4

Ship

Open a PR, run CI, deploy to staging or prod with rollback baked in.

FAQ

Common questions

Which models can I use?

MiMo (Pro / Lite), Claude Sonnet/Opus, DeepSeek V3, GPT-4 family, Gemini Pro, Doubao, MiniMax, and a dozen open-weights served from our edge fleet. Switch with one CLI flag.

Does NebulaCraft store my code?

By default, no. Project trees are mounted ephemerally into sandboxed runtimes and discarded after each task. Optional encrypted memory graphs live only on your account.

How do you handle secrets?

Per-project encrypted vault. Values are never sent to the model — the agent receives opaque handles like $secret.STRIPE_KEY and our runtime injects the real value at call time.

Can I bring my own model endpoint?

Yes. Point the studio at any OpenAI-compatible endpoint. We support custom routing rules, fallbacks, and budget caps.

What about open-source?

The CLI, the planner core, and the sandbox runtime are MIT-licensed. The hosted studio offers extras like the memory graph, telemetry, and team features.
